## AI 应该如何“阅读”一篇文章？

阅读是人类获取信息的一种方式。我们阅读一篇文章或一本书，在脑海里整理信息，形成自己的观点。

让 AI 帮忙阅读，最常见的方式就是把一整篇文章交给它，让它做总结、提炼、归纳，甚至生成图谱。但这里有一个问题：**AI 的阅读和人类的阅读不一样**。

我试过让 AI 根据一篇文章生成图谱，结果往往不尽人意，还需要人工核对、修正和补充。

我时常发现，AI 阅读的问题主要集中在：

- 文章很长，AI 一次吃不下
- AI 的阅读不受约束，容易跑题、胡编乱造
- AI 的阅读不受关注点约束，容易漏掉用户关心的内容

这些问题让我开始思考：**在接入知识图谱之前，能否先建立一个受关注点约束、处理结果可核对的文档预处理过程？**

要把一篇文档作为一个模块接入用户已有的 Ontology 知识图谱，首先需要从文档中整理出符合其关注点的信息。这篇文章讨论的，就是接入之前的预处理过程：输入文本与 ontology，输出一张包含关键词、定义及相关证据的词表，为后续接入做准备。

对此，我有两个方面的想法：

第一，用输入的 ontology 明确 AI 的关注点，让它知道要从文档中提取什么信息。

第二，把 AI 的阅读过程拆分为两个阶段：粗读和细读。和人一样，先粗读一遍，了解文章大概在讲什么，然后再细读，按关注点去提取信息。

## Ontology（本体论）是什么

在人工智能领域，ontology 是对某个领域的知识进行建模的方式。它可以用来描述一个领域中的概念、属性和关系。

在我们的场景里，用大白话说，**ontology 就是一份「用户关心什么」的描述清单。**

它可以约定：要关注哪些类型（比如术语、人物、事件）、每种类型大概长什么样、输出时结果表该有哪些栏。它就像一份阅读提纲，约定我们带着哪些关注点阅读，也指导后续的信息抽取。

同一篇文档，换一份 ontology，关心的关键词类型可以完全不一样。所以抽取不能「模型随便总结一通」，而要**按当前这份 ontology 来问、来填、来检查。**

在这个预处理模块中，ontology 提供处理要求，文本提供待处理的内容。接下来，我们依次通过候选发现、粗读、细读与整理，将文本中的信息汇集成符合关注点的关键词表。

## 候选发现：准备一张候选词表

正式阅读之前，我们先找出候选词。就像阅读时先圈出值得留意的词语，再在后续阅读中逐步补充批注，这一步先找出文档中可能值得关注的内容，并记录它们的位置。

这一步一般不用语言模型，而是先用低成本的算法清理文档、识别候选词。它解决一个问题：**文档的关键点有哪些？分别在哪些位置？**

这些内容会汇集到一张**候选词表**中。它是贯穿整个处理过程的数据结构：候选发现阶段先建立词表，细读时不断补充证据和建议，最后经过整理与归一化，这张表就成为最终的关键词表。

![候选词结构：名称、类型及多个出现位置](/static/blog/2026-10-28-doc-ontology-keywords/01-candidate-structure.png)

候选词表里面应该包含：

- 文档中出现的所有可能的关键词（术语、人物、事件等）
- 关键词出现的位置（章节、段落、页码等）

这张表不需要一次填完，后续模型会对照 ontology 这份阅读提纲，逐步补充、核对和筛选其中的内容。候选词表的质量直接影响后续抽取的效率和准确性。

## 粗读：画出文章的地图

粗读关注文章和章节的结构与主题，帮助我们了解全文梗概。它就像画出一张文章的地图，让后续细读每个片段时，都知道这段内容处于什么位置、与全文有什么联系。粗读之后，我们应该拿到：

- 一个文章梗概（文章 Meta）
- 每个章节的梗概（章节 Meta）

![文章 Meta 与章节 Meta 的内容及层级关系](/static/blog/2026-10-28-doc-ontology-keywords/02-document-meta.png)

为了节省预算，粗读可以抽样进行。一般来说，文章的开头和结尾格外重要，所以我们可以取全文以及每一章的开头和结尾段落，作为粗读的样本。这足以形成文章梗概了。

## 细读：带着关注点做批注

现在我们手上有四个东西：

1. 文档正文
2. 一份阅读提纲：当前的 ontology（关注类型与填表规矩）
3. 一张待完善的候选词表（包含文档中出现的所有可能的关键词，以及关键词出现的位置）
4. 一张地图：文档 Meta 和章节 Meta（粗读的结果）

有了这些东西，细读就有了明确的方向。

细读往往需要对正文分片，这里暂不讨论如何分片，假设我们已经把文章分成了若干个片段。每个片段都可以单独处理，按关注点去提取信息。

![细读循环：逐片段关联证据与批注，持续更新同一张候选词表](/static/blog/2026-10-28-doc-ontology-keywords/03-close-reading-loop.png)

细读的过程是一个循环：每次处理一个分片。模型对照 ontology 这份阅读提纲检查信息，并把建议附在候选词表上。就像我们读到相关段落时，在圈出的词语旁写下批注，这一步把候选词与对应的原文联系起来，也就是**证据关联**过程。

完成之后，候选词表应该长这样：

- 关键词1：（出现位置1，参考建议1）、（出现位置2，参考建议2）、（出现位置3，参考建议3）
- 关键词2：（出现位置1，参考建议1）、（出现位置2，参考建议2）

![细读后的候选词：各出现位置关联原文证据、参考建议与批注](/static/blog/2026-10-28-doc-ontology-keywords/04-candidate-evidence.png)

## 整理：把阅读笔记归入词表

读完文章，还需要整理阅读笔记。模型汇总候选词表中积累的证据和建议，把重复、相似的关键词进行合并，并对每个关键词进行定义。这个过程就是**归一化**，让阅读过程中陆续记录的内容形成统一的结果。

![分批整理候选词表，跨批次归并为关注点定义表](/static/blog/2026-10-28-doc-ontology-keywords/05-normalization.png)

至此，这张不断完善的候选词表就成为我们想要的最终关键词表：对准用户的关注点，并且每个关键词都有定义。

## 示例：用《Attention Is All You Need》提取关键术语

以论文 [《Attention Is All You Need》](https://arxiv.org/abs/1706.03762) 为例，我们把论文文本和术语类 ontology 作为输入，关注模型架构、注意力机制及相关组件，输出带有定义和原文关联的候选词表。

下面摘录 Miremo 的一组历史测试数据，沿用同一条处理链中的三个候选 ID，展示它们从预选到整理的变化。表中的 `CH` 是测试系统的章节编号，`SH` 是正文分片编号，不是论文页码。Meta 和定义均来自实际模型输出；本轮交付仍待评审，尚未正式采纳到知识图谱。

### 预选：候选表里最初有什么？

这一轮使用 JATE 算法建立了 994 条预选候选。先看其中三条，保留它们最初的名称：

| 候选 ID | 预选名称      | 匹配次数 | 出现分片（节选）       |
| ------- | ------------- | -------- | ---------------------- |
| J0016   | `attention`   | 101      | SH002、SH003、SH004 等 |
| J0055   | `transformer` | 28       | SH003、SH004、SH006 等 |
| J0630   | `feed`        | 7        | SH010、SH012、SH020 等 |

这里的匹配次数是预选程序记录的出现次数，不代表有效证据数量。比如 `feed` 只有一个不完整的词形，它是否对应一个专业概念，还需要结合正文判断。

展开 `J0630`，可以看到候选表实际保存的字段。下面省略了算法评分、版本和历史记录等字段，`mentions` 只展示第一处匹配：

```json
{
  "id": "J0630",
  "name": "feed",
  "occurrences": 7,
  "mention_shard_ids": ["SH010", "SH012", "SH020", "SH026", "SH033"],
  "status": "preselected",
  "definition": "",
  "classification": null,
  "mentions": [
    {
      "highlight_spans": [
        {
          "shard_id": "SH010",
          "start": 104,
          "end": 108
        }
      ],
      "match_method": "normalized",
      "language": "en"
    }
  ]
}
```

此时 `definition` 为空，`classification` 也尚未确定。`start` 和 `end` 表示清理后的分片文本中的字符范围，采用从 0 开始、包含起点而不包含终点的记录方式。它们让后续处理可以定位回原文，而不只是拿到一个孤立的词。

### 粗读：得到文章 Meta

这一轮把 Meta 分为两部分：全文通用内容放在 `shared` 下，当前 ontology 的关注项单独保存。以下摘录其中三个字段：

| 字段                    | 真实输出（节选）                                                                                                                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全文梗概 · overview     | 本文介绍了Transformer架构，一种完全基于注意力机制的新颖网络结构，摒弃了传统的循环和卷积。该模型在机器翻译任务上取得了优于现有最佳结果的BLEU分数，且训练成本显著降低，并展示了在其他任务（如句法分析）上的良好泛化能力。 |
| 内容角色 · content_role | SH001为版权声明；SH002-SH004包含标题、作者信息及摘要，确立了文档的核心贡献（Transformer架构）和实验结果；SH050-SH056为参考文献列表；SH057-SH059展示了注意力可视化示例，用于解释模型内部机制。                           |
| 抽取关注点 · focus      | 关注核心模型架构及其关键组件。重点识别‘Transformer’作为整体架构，‘attention mechanism’作为核心机制，以及其具体变体如‘scaled dot product attention’、‘multi-head attention’和‘self-attention’。                          |

这些梗概来自粗读抽样，不是对每个分片完成细读后的最终结论。实际记录还保存了各字段对应的 `shard_ids`，例如上面的全文梗概关联 `SH002`、`SH003` 和 `SH004`。

章节同样分别保存内容梗概和抽取关注点。下面选取两个真实章节的输出节选：

| ------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CH05 · Model Architecture | 本章详细阐述了Transformer模型的整体架构，包括编码器（Encoder）和解码器（Decoder）的结构。 | 关注Transformer整体架构及其核心组件的专业定义。重点识别‘Transformer’作为基于自注意力和前馈网络的序列转导模型；‘Encoder’和‘Decoder’作为堆叠的自注意力和点式全连接层结构；‘Positional Encoding’作为注入序列顺序信息的正弦/余弦函数机制；‘Embeddings’及‘Softmax’作为输入输出向量化及概率预测的标准组件。                                                                                                                                         |

`CH05` 的这些粗读字段关联 `SH009`、`SH010`、`SH011`、`SH027`、`SH028` 和 `SH029`；`CH06` 的梗概关联 `SH030`，关注点关联 `SH030` 和 `SH033`。细读时，这些信息帮助模型理解当前片段在全文中的位置。

### 细读与整理后：同一批词变成什么样？

以 `feed` 为例，细读到 `SH026` 时，模型留下了这条关联理解：

> 作为标题及正文中'Feed Forward Networks'（前馈网络）的一部分，指代该特定网络结构类型。

整理阶段随后结合相关词条与原文证据，将这一组候选归并为 `position-wise feed forward network`。最终记录保留了 `J0039`、`J0630`、`J0770`、`J0078` 和 `J0332` 五个原候选的映射，别名中包括 `feed forward network`、`FFN` 和 `position-wise feed-forward network`。这个变化来自上下文和归并记录，并非把所有出现的 `feed` 都机械替换成同一个术语。

本轮整理后的交付表包含 160 条候选，下面展示与前面三个 ID 对应的真实结果：

| 保留 ID | 规范名称                           | 定义（原始输出）                                                                                                                                                                                                                                                                                                                            | 定义所关联的分片           |
| ------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| J0016   | Attention mechanism                | 指Transformer架构中用于建模序列依赖关系的核心计算模块，完全替代了传统的循环和卷积结构。其基本形式是一种注意力函数，将查询（Query）和一组键值对（Key-Value pairs）映射到输出，其中查询、键、值和输出均为向量，输出是值的加权求和。在本文中，具体实现包括缩放点积注意力（Scaled Dot Product Attention）和多头注意力（Multi Head Attention）。 | SH003、SH014、SH020、SH022 |
| J0055   | Transformer                        | 指一种全新的简单网络架构，完全基于注意力机制，摒弃了传统的循环和卷积结构。它用于序列转导任务，允许更显著的并行化计算，并通过堆叠自注意力和点式全连接层构建编码器和解码器。它是第一个完全基于注意力的序列转导模型。                                                                                                                          | SH003、SH008、SH011        |
| J0630   | position-wise feed forward network | 指Transformer编码器和解码器每一层中包含的全连接前馈网络，应用于每个位置且彼此独立相同。由两个线性变换组成，中间夹有一个ReLU激活函数。其数学表达为 FFN(x) = max(0, xW1 + b1)W2 + b2。输入和输出维度为d_model，内部层维度为d_ff。                                                                                                             | SH026                      |

最终记录还保留了别名、原候选 ID、逐条证据、修改说明及复核意见。上表只选择与阅读主线有关的字段；其中 `attention` 归入 `Attention mechanism`，`transformer` 规范为 `Transformer`，不完整的 `feed` 则经上下文判断与同组候选整理形成完整名称。

从预选名称和出现位置，到章节背景、细读批注，再到有依据的定义，这些变化就体现在同一张持续完善的词表中。它构成了本文所说的关注点定义表，也为后续文档接入知识图谱提供了材料。

## 小结

![文档预处理整体数据流：文本与 Ontology 输入，经候选发现、粗读、逐片段细读和整理归一化，输出关注点定义表，为后续知识图谱接入提供材料](/static/blog/2026-10-28-doc-ontology-keywords/06-overall-data-flow.png)

输入文本与 ontology，经过候选发现、粗读、细读与整理，输出包含关键词、定义及相关证据的词表，这就构成了一个可执行、可核对、可迭代的文档预处理模块。贯穿其中的始终是同一张词表，它随着阅读逐步完善，最终成为供后续接入使用的结果。

后续可以利用这些结果开展关系抽取等工作，再将文档作为一个模块接入用户已有的 Ontology 知识图谱。本文讨论的预处理过程，正是在为这一步准备材料。
